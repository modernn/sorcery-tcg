<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumed lock -> existing source roots | The lock may resolve incomplete, substituted, aliased, or mutable evidence and grants no new acquisition authority. |
| existing roots -> final-contract candidates | Two roots could diverge or final schemas could transform them differently. |
| verified candidate -> selected revision/receipt | A stale ID, wrong root, overwrite, or unsafe receipt could misbind later consumers or leak private evidence. |
| selected revision -> Git/package/runtime | Final publication could expose protected content or reintroduce network/latest selection. |

## STRIDE Threat Register

| Threat ID | Category | Severity | Component | Disposition | Mitigation Plan |
|-----------|----------|----------|-----------|-------------|-----------------|
| T-01-57 | Spoofing / Tampering | high | existing roots | mitigate (blocking) | Shared content plus hash verification over both roots and immutable before/after maps. |
| T-01-58 | Tampering / Repudiation | high | dual candidate build | mitigate (blocking) | Fixed new ID, independent builds, canonical file-map equality, external root recomputation, and old-revision immutability. |
| T-01-59 | Spoofing | high | selection/receipt | mitigate (blocking) | Write-once install and exact ID/root binding; stale/latest/mismatched selections fail. |
| T-01-60 | Information disclosure | high | release surfaces | mitigate (blocking) | Full Plan 12 scanner over history/worktree/index/package plus content-free diagnostics before commit. |
| T-01-61 | Elevation / legal boundary | high | consumed authorization | mitigate (blocking) | No acquisition, retry, mutation, distribution, hosting, API, artwork, or permission inference; existing bytes only. |
| T-01-SC | Tampering | low | package installs | accept | No dependency is added; use existing Node, PowerShell, Zod, and project helpers. |
