<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| raw bytes/unknown JS -> canonical identity library | Attacker-controlled structure can consume CPU/memory or exploit permissive parsing. |
| identity document -> persisted hash | Tampering must change or invalidate the recorded content hash. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering / DoS | `parseAuthorityJson`, `canonicalJson` | mitigate | Enforce byte/depth/record/node/string/diagnostic caps, reject cycles/duplicates/unsupported values, and test exact failures. |
| T-01-07 | Tampering | path fields | mitigate | Schemas reject absolute and traversal path syntax; canonical root/symlink resolution is implemented and tested in Plan 04. |
| T-01-08 | Spoofing | `SourceRecord.url` | mitigate | Permit reviewed official HTTPS URLs only and keep the distinction between URL review and hash integrity explicit. |
| T-01-09 | Tampering | `CanonicalArtifact` | mitigate | Recompute SHA-256 over the canonical identity document and reject mismatches/unsupported schema versions. |
| T-01-10 | Information disclosure / legal | source storage policy | mitigate | Strict enum defaults to no implicit permission; prohibited storage is rejected by the Plan 04 validator and Plan 05 publisher. |
| T-01-SC | Tampering | Zod install | mitigate | Consume the exact Approved version from the Wave 0 lockfile; introduce no new package. |
</threat_model>
